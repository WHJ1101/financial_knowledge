### 0.3 相较 v1 的关键修订（Codex Review 落实）

1. **R1 报告个人态分离**：`reports` 内容与 `user_report_states`（标星/归档/已读）分离；报告默认私有、发布后共享。v1 把 reports 整个当公共共享是错的。
2. **R2 证券身份提前**：`stocks.code` 是主键，多用户加同一支票会冲突；`instruments`+`watchlist_items`(UUID) 提前到 M1，撤销 v1 的"延后到 M-Ext"。
3. **R3 BYOK 全覆盖**：引入 `LlmExecutionContext`，research/信号抽取/持仓分析/辩论/系统日报所有 LLM 调用都明确执行身份，不止辩论。
4. **R6 可撤销 session + CSRF**：改数据库 session（禁用用户即时失效、改密踢下线），写请求加 CSRF 校验。
5. **R5 LLM URL SSRF 防护**：用户自填 `api_url` 经 scheme/IP/重定向校验 + allowlist。
6. **R7/R8 队列与 schema 职责澄清**：procrastinate 唯一队列（删 v1 `debates.lease_until` 手写描述）；业务表归 Alembic，队列表与 Checkpoint 表各自初始化。
7. **R9/R10 事实修正**：端点是 **~50 个 method 声明**（非 26）；迁移基线**动态生成快照**，不写死历史数字；报告缺失/孤儿文件进 reconciliation 清单。
8. **自查补充（Review 未提）**：`automation_tasks` 是系统任务写公共数据，改 `scope=system`，**不按 owner 隔离**；`secid_map` 职责被 `instruments.quote_secid` 覆盖，M1 收敛。
9. **按 <10 人降级（§16）**：`audit_events`、全套限流、完整密钥轮换 rewrap 推迟或降级，不做 SaaS 全套。

## 1. 现状基线（已通读代码）

### 1.1 运行时与规模

- 前端：Preact + `@preact/signals` + preact-router，Vite 构建，SPA。约 3671 行（`src/`）。
- 后端：Node 原生 `http` 服务（`server/index.js`），声明式路由表（`server/api-routes.js`，**约 50 个 method 声明**，非 26；GET20/POST24/DELETE5/PUT1）。`better-sqlite3` 单文件读写。约 6291 行（`server/` + `lib/`，不含测试）+ 2228 行测试。

### 1.3 值得保留的既有设计（迁移时对齐，勿丢）

- **声明式路由表**（`api-routes.js`）：`public` 显式标注鉴权豁免——迁到 FastAPI 用依赖注入实现同等语义。
- **fire-and-forget + 进度轮询**（`stock-analyzer.js` / `Portfolio.jsx:useAnalysisPoller`）：异步任务范式已验证，辩论轮询沿用（执行载体升级为独立 worker，见 §7.5）。
- **调度重叠防护 + 先占位再执行**（`scheduler.js:26`）：任务不重复触发的幂等逻辑，迁到 worker 周期任务时保留语义。
- **无鉴权禁止对外监听**（`index.js:24` `assertHostIsSafe`）：安全护栏，迁移后等价保留（多用户下改为"未配置超管禁止对外监听"）。
- **报告 HTML 鉴权访问**（`index.js:47`）：现有报告文件本就经鉴权提供，多用户下升级为经 FastAPI 属主/可见性校验（§9.4），**Caddy 不直接暴露 `data/reports/`**。
- **数据诚实性**（辩论文档 §1.3）：四面证据真实性不均衡、dataGaps 强制声明、裁判降权——业务契约，不可弱化。

## 2. 目标架构

### 2.1 运行拓扑（多用户版）

```
浏览器（多个可信用户）
  │ HTTPS
  ▼
Caddy  ── 自动 TLS + 反向代理，静态与 /api 同源
  │
  ▼
api (uvicorn/FastAPI)  ── serve /api/v1/* + 创建任务（入队即返回）；**不跑调度器**
  │                       （前端静态由 Caddy 服务；报告内容经 API 鉴权流式返回）
  ▼
PostgreSQL  ── 业务数据 + procrastinate 队列 + LangGraph 检查点
  ▲
  │ procrastinate 领取（底层 SKIP LOCKED，业务代码不手写）
  ▼
worker (独立进程)  ── procrastinate worker：领取辩论/采集任务 + **持有周期调度**，用发起者 BYOK key
  │
  └── 外部 Provider：东财行情/基本面、akshare 宏观、各用户 LLM(OpenRouter 等)、飞书
```

> **调度职责唯一化（二轮 review 必须项 1）**：API 只创建任务；**procrastinate 是唯一队列**；worker 领取任务**并持有周期调度**（procrastinate 原生 cron 支持多 worker 下同一周期只投递一次）；**业务代码不实现 `SKIP LOCKED`、不用 APScheduler、不双队列**。

**与 ChatGPT 草案的取舍对比（多用户目标下重新评估）**：

| 维度 | ChatGPT 草案 | 本方案 | 理由 |
|---|---|---|---|
| 进程模型 | API / Worker 分进程 | **采纳：api + worker 分进程** | 多用户并发发辩论，长任务不能占 API 进程 |
| 任务队列 | workflow_runs + 租约/幂等键/行锁 | **采纳：procrastinate（PG 队列）** | worker 需领取机制防重复领取、重复烧 key；用 PG 而非 Redis，不引额外组件 |
| 反向代理 | nginx | **改用 Caddy** | 公网需 TLS；Caddy 自动证书 + 极简配置，比 nginx+certbot 更适合小规模 |
| 进度通道 | SSE 强制 | **轮询起步，SSE 列 M8 增强** | <10 人轮询压力可忽略，不提前引入 SSE 复杂度 |
| 用户体系 | 多租户 SaaS（明确不做） | **邀请码注册 + 混合数据归属** | 少数可信用户，不需要完整多租户隔离/计费/合规 |
| Compose 服务 | frontend-build + nginx + api + worker + postgres（5） | **caddy + api + worker + postgres（4）** | 前端构建产物进 api 镜像，省一个构建服务 |

> 采纳 ChatGPT 草案的：API/Worker 分进程、任务队列领取机制、统一证券身份（§4）、宏观数据模型（§6）、Provider 隔离（§6）、依赖方向约束（§2.3）。仅在 SSE、反代选型、用户体系量级上按"小范围可信用户"裁剪。

### 2.2 目录结构（Monorepo 单仓）

```text
financial_knowledge/
├── frontend/                    # React + TS + Vite
│   └── src/{api,pages,components,hooks,store}
├── backend/
│   ├── app/
│   │   ├── main.py              # FastAPI app + lifespan（**不含调度器**）
│   │   ├── worker.py            # ★procrastinate worker 入口：领取任务 + 持有周期调度
│   │   ├── config.py            # pydantic-settings 读 env
│   │   ├── db.py                # SQLAlchemy engine / Session
│   │   ├── api/                 # APIRouter 按领域拆分
│   │   ├── core/                # auth(session) / security(CSRF) / crypto(BYOK) / queue(procrastinate 装配)
│   │   ├── models/              # SQLAlchemy 2.0 ORM
│   │   ├── schemas/             # Pydantic 出入参
│   │   ├── services/            # 领域服务：用户/报告/持仓/压力/行情
│   │   ├── providers/           # 外部数据源封装（东财/akshare/飞书）
│   │   ├── llm/                 # langchain-openai 封装（按用户 key 构造 client）
│   │   └── agents/decision/     # LangGraph 辩论图
│   ├── alembic/
│   ├── scripts/{import_sqlite.py,verify_migration.py}
│   ├── tests/
│   └── pyproject.toml
├── data/                        # 运行时目录；app.db 迁移后归档
├── infra/{caddy/Caddyfile,docker/}
├── docker-compose.yml           # caddy + api + worker + postgres
└── .doc/
```

**api 与 worker 共享同一 Python 包**（models/services/agents/providers），仅入口不同（`main.py` vs `worker.py`），不复制业务逻辑（对齐 ChatGPT 草案 ADR）。

### 2.3 依赖方向（架构纪律）

```
API 路由 (api/)
    ↓ 只解析请求、调服务、映射 HTTP 状态
领域服务 (services/ + agents/)
    ↓ 业务逻辑，依赖注入 Provider/LLM/Repo
模型与 Provider (models/ + providers/ + llm/)
    ↓
PostgreSQL / 外部 HTTP / LLM API
```

约束（写码时守住）：
- 领域服务不 import FastAPI 对象（Request/Response）。
- LangGraph 节点不直接拼 SQL、不直接持有 HTTP 请求对象；取数走 Provider，落库走服务。
- Provider 只负责采集/解析/标准化/报告数据源状态，不含业务判断。
- 纯计算（技术指标、压力指数）保持无 I/O 纯函数，可直接单测。
- 前端只消费 OpenAPI 生成的类型，不硬编码后端字段名。

## 3. 技术栈与依赖

### 3.1 后端依赖（pyproject.toml）

| 用途 | 库 | 说明 |
|---|---|---|
| Web 框架 | `fastapi` + `uvicorn[standard]` | ASGI，自带 OpenAPI |
| 配置 | `pydantic-settings` | 读 env，替代 `authConfig()` 的分散读取 |
| ORM | `sqlalchemy>=2.0` | 同步 Session 起步 |
| 迁移 | `alembic` | 替代 `db.js` 建表 + `migrate.js` |
| PG 驱动 | `psycopg2-binary` | ★M0 定案：走 `SQLAlchemyPsycopg2Connector` 实现同事务 defer（psycopg3 无对应 SQLAlchemy 连接器）；SQLAlchemy DSN `postgresql+psycopg2://` |
| 外部 HTTP | `httpx` | 替代裸 fetch，行情/基本面/飞书 |
| 宏观数据 | `akshare` | **本次真收益**：CPI/PMI/GDP/社融/利率 |
| LLM 编排 | `langchain-openai` + `langgraph` | 指向现有 OpenRouter base_url |
| **LangGraph 检查点** | `langgraph-checkpoint-postgres` + `pycryptodome` | ★`PostgresSaver`（`langgraph.checkpoint.postgres`），首用 `.setup()`；加密 `EncryptedSerializer.from_pycryptodome_aes()` |
| Cookie 签名 | `itsdangerous` | **仅用于 CSRF token 签名**（session 走 DB，不再签名 session；见 §9.1/9.2） |
| 密码哈希 | `argon2-cffi` | ★M0 定案：直用成熟 argon2 实现（`PasswordHasher.hash/verify`）；放弃 pwdlib（0.3.0 仍 Beta），本项目只需 argon2 一种 |
| **BYOK 加密** | `cryptography`（Fernet） | 用户 LLM key 对称加密落库，密钥由 `BYOK_MASTER_KEY` 派生 |
| CSRF | double-submit（itsdangerous 签名） | 写请求校验 `X-CSRF-Token` 与非 HttpOnly cookie 一致 + Origin 校验 |
| 任务队列 + 调度 | `procrastinate` | **唯一队列 + 唯一调度器**（原生 cron，多 worker 同周期只投递一次）；不引 Redis、不用 APScheduler |
| 测试 | `pytest` + `pytest-asyncio` | |
| 格式/类型 | `ruff` + `mypy` | 对齐个人 Go 规则的质量基线 |

> **M0 依赖核实结论（官方文档，2026-07-14）**：
> - **入队事务（P0）定案**：procrastinate 官方仅 `SQLAlchemyPsycopg2Connector`（psycopg2）支持 SQLAlchemy Connection 同事务 defer；`SyncPsycopgConnector` 是 psycopg3 但非 SQLAlchemy 集成。**SQLAlchemy + psycopg3 无同事务方案**。→ 选 **psycopg2 + `SQLAlchemyPsycopg2Connector`**，`task.configure(connection=conn).defer(...)` 与业务写同一 SQLAlchemy 事务提交，**删除 outbox 子系统**（§4.7 方案 B）。
> - **密码（P0）定案**：pwdlib 0.3.0 仍 Beta（Development Status 4）→ 改用 **argon2-cffi**（成熟、Python 3.13 兼容、argon2 官方绑定）。
> - **LangGraph**：`langgraph-checkpoint-postgres` 提供 `PostgresSaver`，首用需 `.setup()` 建表；`EncryptedSerializer.from_pycryptodome_aes()` 读 `LANGGRAPH_AES_KEY`（**须 16/24/32 字节原始 AES key**，base64 存储需先解码）。
> - 三库版本 M0 pin 锁定写入 pyproject.toml。

**异步策略明确**：路由默认用 `def`（同步），FastAPI 自动丢线程池，SQLAlchemy 同步 Session 好写好调试。仅**外部并发抓取**（行情批量、宏观多序列，对应现有 commit `a8afab4` 的并发化）用 `httpx.AsyncClient` + `asyncio.gather` 局部 async。不全链路 async，避免 async ORM 的心智负担。worker 侧辩论任务本身耗时长，串行领取执行即可。

### 3.3 端点映射（旧路由是迁移清单，非冻结契约）

**Codex Review R10 修正**：现有 `api-routes.js` 实际是**约 50 个 method 声明**（非 v1 说的"26 端点 1:1 冻结契约"），且不少查询直接读全局数据。故旧路由表作为**迁移清单**，新 `/api/v1` 按**领域契约重新设计**——隔离资源端点强制带属主过滤、报告端点区分共享/私有、新增用户与 BYOK 端点。响应 shape 尽量对齐旧版以复用前端，但**不承诺字节级冻结**。核心映射：

## 4. 数据模型

### 4.1 迁移原则：证券身份提前到 M1（Review R2 修正 v1）

v1 主张"1:1 复刻 12 表、证券身份延后到 M-Ext"。**Codex Review R2 指出这在多用户下不成立**：`stocks.code` 是主键（实测 `code TEXT PRIMARY KEY`），两个用户加同一支票会主键冲突，加 `owner_id` 也解决不了。故 **`instruments` + `watchlist_items` 提前到 M1**，这不是优化而是多用户前提。

```text
instruments                       -- 统一证券身份，公共共享
├── id             UUID PK
├── asset_class    TEXT           -- ★equity / etf / open_end_fund / hk_stock / us_stock（规范枚举）
├── exchange       TEXT           -- ★SSE / SZSE / HKEX / NASDAQ / NYSE / OTC_FUND（规范交易所）
├── canonical_symbol TEXT         -- ★纯数字/字母主体：301308 / 159995 / 014662 / 00100
├── display_code   TEXT           -- 展示原样：SZ301308 / 159995 / OF.014662（保留用户可读）
├── name           TEXT
├── market         TEXT           -- ★仅展示标签（创业板/基金/ETF/美股…），不参与唯一约束
├── provider_ids   JSONB          -- ★各 Provider 标识集合，如 {"eastmoney":"0.301308","fund":"OF.014662"}
├── source / active / created_at / updated_at
UNIQUE(exchange, asset_class, canonical_symbol)   -- ★规范化唯一键，不再用 (market, code)
```

**证券身份规范化（三轮 review 必须项 3，实测数据支撑）**：现有真实数据混用 `SZ301308`/`301308`/`159995`/`OF.014662`/`1.588080`/`0.159915`，`market` 是"创业板/基金/ETF/美股/深市主板"等**展示标签**——`UNIQUE(market,code)` 不稳。故：
- **唯一键 = `(exchange, asset_class, canonical_symbol)`**：`canonical_symbol` 是剥离前缀的纯代码主体，`exchange`+`asset_class` 消歧（同号码可能一个是 ETF 一个是场外基金）。
- **`market` 降为纯展示字段**，不参与唯一性。
- **`provider_ids` JSONB** 收敛各源标识（东财 `0.301308`、场外基金 `OF.014662`），替代单一 `quote_secid`——迁移期 `secid_map` 的 14 条按 `kind`（exchange/fund）归入对应 provider key。
- 迁移脚本用**规范化函数** `normalize(code, market) → (exchange, asset_class, canonical_symbol)` 处理存量，映射失败的标的进 reconciliation 清单人工确认，不硬塞。

其余表 SQLAlchemy 2.0 `Mapped[]` 声明式建模。**类型映射**（SQLite→PG）：
- `INTEGER` 布尔（`starred`/`archived`/`enabled`）→ PG `boolean`，`0/1` 转 `false/true`。
- JSON `TEXT`（`tags`/`related_assets`/`metadata` 等）→ PG `JSONB`，迁移时 `json.loads`；模型用 SQLAlchemy `JSON` 类型，**去掉散落的手动序列化**。
- **时间戳统一 `timestamptz`**（Review R12 采纳，撤销 v1 的"保留字符串"）：全新 schema 一步到位，迁移脚本解析旧 ISO 字符串，**解析失败即停止报错，不静默写 NULL**。自然日用 `date`，宏观周期用专门字段。

### 4.2 用户体系、Session、邀请码（Review R6/R13）

```text
users
├── id UUID PK / username TEXT UNIQUE
├── password_hash TEXT             -- ★argon2（argon2-cffi）
├── role TEXT CHECK(role IN ('superadmin','member'))
├── status TEXT CHECK(status IN ('active','disabled'))
└── created_at / updated_at

sessions                          -- ★数据库 session，支持撤销（R6）
├── id UUID PK
├── user_id UUID FK→users
├── token_hash TEXT UNIQUE         -- cookie 只存随机 token，DB 存其 HMAC 摘要
├── expires_at / revoked_at / last_seen_at / created_at

invite_codes                      -- 仅超管生成，带过期 + 单次使用
├── id UUID PK
├── code_hash TEXT UNIQUE          -- 存摘要，code 仅生成时展示一次
├── code_hint TEXT                 -- 便于超管辨识
├── created_by UUID FK→users       -- 必为 superadmin
├── expires_at TIMESTAMPTZ
├── used_by UUID FK→users / used_at / revoked_at / created_at

user_llm_configs                  -- BYOK，key 加密（§9.3）
├── user_id UUID PK FK→users
├── api_key_ciphertext TEXT        -- ★Fernet 密文，绝不明文
├── api_url TEXT / model TEXT
├── key_version INT                -- 预留轮换（本期不实现完整 rewrap，§16）
└── updated_at
```

Cookie 只存随机 session token；DB 存 token 的 HMAC 摘要。每次请求查 `sessions` + `users` 拿最新状态与角色（**不信 cookie 里的 role**），从而支持：禁用用户即时失效、改密撤销全部 session、单设备登出、超管撤销指定 session。邀请码注册用原子 `UPDATE ... WHERE used_at IS NULL AND revoked_at IS NULL AND expires_at > now()`，受影响行数必为 1 才在同事务建用户，防并发复用同一码。

### 4.3 报告共享/私有 + 个人阅读态（Review R1 修正 v1）

**Codex Review R1 指出 v1 硬伤**：v1 把 `reports` 整个划为"公共共享"，但 `starred`/`archived`/`status(已读)` 是**每个用户各自**的状态（实测确为 reports 表级字段），共享后 A 标星会污染 B。修正为内容与个人态分离：

```text
reports                           -- 报告内容本体（全字段迁移，实测 32 条全部在用这些字段）
├── id TEXT PK
├── owner_id UUID FK→users         -- 创建者（导入 token 场景=超管，见 §3.4/§9.4）
├── visibility TEXT CHECK(visibility IN ('private','shared'))  -- ★默认 private
├── title / topic / type / summary
├── type_label TEXT                -- 保留（展示用，32/32 有值）
├── origin / origin_label TEXT     -- 保留（来源标签，32/32 有值）
├── source TEXT
├── file TEXT                      -- HTML 相对路径
├── local_date TEXT                -- 保留（业务自然日，32/32 有值）
├── tags JSONB / highlights JSONB  -- TEXT→JSONB（highlights 32/32 非空）
├── meta JSONB                     -- ★归拢展示杂项：accent(主题色) + wiki_path(源路径)
├── content_status TEXT DEFAULT 'ok' CHECK(content_status IN ('ok','missing'))
└── created_at / updated_at
-- 废弃：status/starred/archived 不进 reports（迁入 user_report_states，见下）

user_report_states                -- ★个人阅读态，独立于报告本体
├── user_id UUID FK→users
├── report_id TEXT FK→reports
├── read_at TIMESTAMPTZ            -- ★迁移：旧 status='read' → read_at=报告 updated_at；'new'→NULL
├── starred BOOL / archived BOOL   -- 旧 reports.starred/archived 迁到超管这一行
├── updated_at
PRIMARY KEY(user_id, report_id)

report_asset_links                -- ★报告↔证券关联（现有接口仍在用，实测空表但保留）
├── id UUID PK
├── report_id TEXT FK→reports
├── instrument_id UUID FK→instruments  -- 由旧 asset_code/market 归一到证券身份
├── relation TEXT DEFAULT 'related' / source TEXT DEFAULT 'manual'
├── created_at / updated_at
UNIQUE(report_id, instrument_id, relation, source)  -- 继承现有唯一约束
-- 可见性/权限：继承所属 report 的 visibility（§3.4 assets 接口按 report 属主校验）

user_signal_states                -- ★信号个人态（信号本体公共，确认/忽略按人隔离）
├── user_id UUID FK→users
├── signal_id TEXT FK→community_signals
├── state TEXT CHECK(state IN ('unread','confirmed','ignored'))
├── updated_at
PRIMARY KEY(user_id, signal_id)
```

**报告字段迁移决策（三轮 review 必须项 2，实测 32 条全部在用）**：

| 旧字段 | 去向 | 说明 |
|---|---|---|
| `title/topic/type/summary/source/origin/file` | 保留同名 | 核心元数据 |
| `type_label/origin_label/local_date` | **保留**（32/32 有值） | 展示标签 + 业务自然日 |
| `tags/highlights` | TEXT→**JSONB** | highlights 32/32 非空，非废弃 |
| `accent/wiki_path` | **归入 `meta` JSONB** | 主题色 + 源 wiki 路径，非核心查询字段，收进 meta |
| `status`（new/read） | **→ `user_report_states.read_at`** | 旧 `read`→read_at=updated_at、`new`→NULL；实测 20 read / 12 new |
| `starred`（3 条）/`archived`（0） | **→ `user_report_states`** | 迁到超管那一行个人态 |

`report_asset_links` 现有接口（`/reports/{id}/assets`、`/assets/{code}/reports`）仍在用（实测表空但结构在），目标表用 `instrument_id` 替代旧 `asset_code/market`，权限继承所属 report 可见性。

```text
├── instrument_id UUID FK→instruments  -- 统一证券引用
├── procrastinate_job_id BIGINT     -- 关联队列 job；幂等：同 debate 只投一次（§4.8）
├── graph_thread_id TEXT UNIQUE     -- LangGraph 线程 id，服务端生成，前端不可提交
├── status TEXT CHECK(status IN ('queued','running','done','failed','canceled'))
├── progress INT / stage TEXT
├── verdict / confidence            -- 裁判结论冗余，便于列表展示
├── report JSONB                    -- 完整报告（辩论文档 §3.4）
├── error_code / error_message
└── created_at / started_at / finished_at / updated_at

macro_series                       -- ★UNIQUE(source, code)，非仅 code（二轮 review 必须项 5）
├── id UUID PK / source TEXT / code TEXT / name / region / category
├── frequency / unit / value_type   -- value_type: yoy|mom|absolute，明确同比/环比/绝对值
├── source_url / enabled / updated_at
UNIQUE(source, code)

macro_observations
├── id UUID PK / series_id FK
├── observation_period TEXT / period_start DATE / release_at TIMESTAMPTZ NOT NULL
├── value NUMERIC / unit / source / source_url / retrieved_at
├── revision_hash TEXT NOT NULL     -- ★NOT NULL，否则唯一约束对 NULL 无法去重
├── raw_payload JSONB
UNIQUE(series_id, observation_period, revision_hash)
```

**队列职责澄清（Review R7）**：procrastinate 是**唯一队列**，负责排队/领取/重试/租约——**业务代码不手写 `SELECT ... FOR UPDATE SKIP LOCKED`、不自实现 `lease_until`**（已删 v1 该描述）。`debates` 只存**用户可见的业务态**（status/progress/report），通过 `procrastinate_job_id` 关联队列 job。任务函数幂等：同一 `debate_id` 重复执行只更新、不重复建报告。

**宏观数据诚实性铁律**（继承辩论文档 §1.3）：模型 Prompt 只能消费已落库的标准化观测，**禁止用训练记忆补缺失数值**；缺失即在 dataGaps 声明，裁判对该面降权。把辩论文档标注为"⚠️ 半真代理"的宏观面升级为可追溯真实数据——**本次重构对辩论业务的核心增益**。

### 4.7 入队事务方案：M0 定案（三轮 review P0 必须项 1，已核实）

问题：本方案原用 SQLAlchemy + psycopg3，但 procrastinate 官方**没有** SQLAlchemy+psycopg3 的同事务连接器。M0 查官方文档定案：

**采用方案 B——`SQLAlchemyPsycopg2Connector` 同事务 defer（psycopg2）**：
- 驱动改 **psycopg2**（`postgresql+psycopg2://`），procrastinate 用 `SQLAlchemyPsycopg2Connector` 复用 SQLAlchemy engine。
- 创建辩论：在**同一 SQLAlchemy 事务**内插 `debates(status='queued')` + `run_debate.configure(connection=conn).defer(debate_id=...)`，`conn.commit()` 一起提交——业务行与队列 job 原子入库。
- **无需 outbox 表 / dispatcher**（原方案 A 的 outbox 子系统删除，方案更简）。
- 注意（官方 caveat）：唤醒 NOTIFY 仅在 commit 后触发；job INSERT 若失败会污染事务，必要时用 savepoint 隔离 defer。

```python
# 创建辩论（同事务原子入队）
with Session() as session:
    conn = session.connection()  # 复用 SQLAlchemy 连接
    debate = Debate(id=ulid(), status="queued", owner_id=uid, execution_owner_id=uid, ...)
    session.add(debate)
    run_debate.configure(connection=conn.connection).defer(debate_id=debate.id)
    session.commit()   # 业务行 + 队列 job 一起提交
```

**幂等**：以 `debate_id` 为 procrastinate queueing lock / 幂等键，重复投递去重，worker 任务函数只更新该 debate、不重复建报告。

> psycopg3 的连接池/新特性本项目用不到；同步 SQLAlchemy + psycopg2 是最成熟稳定的组合，且唯一能满足"创建即原子入队"这一不变式。

### 4.8 队列表与 Checkpoint 表的 schema 职责（Review R8）

- **业务表**（含上述所有）：由 **Alembic** 管理迁移。
- **procrastinate 表**：用其自带 CLI/SQL 初始化，**不纳入业务 Alembic**，放独立 schema（如 `queue`）。
- **LangGraph checkpoint 表**：用 `langgraph-checkpoint-postgres` 的 `PostgresSaver.setup()` 一次性初始化，放独立 schema（如 `langgraph`），业务 Alembic 不接管第三方内部表。

## 6. 数据源 Provider

### 6.1 Provider 接口（依赖注入，领域层不感知具体源）

```python
class MarketDataProvider(Protocol):
    async def quote(self, ref: InstrumentRef) -> QuoteSnapshot: ...
    async def bars(self, ref: InstrumentRef, period: str) -> list[Bar]: ...

class FundamentalDataProvider(Protocol):
    async def snapshot(self, ref: InstrumentRef) -> FundamentalSnapshot: ...

class MacroDataProvider(Protocol):
    # ★时点口径 + Ref 与表键一致（三轮 review 必须项 6）
    async def series(
        self,
        ref: MacroSeriesRef,          # source + code + region，与 macro_series UNIQUE(source,code) 一致
        as_of: datetime,              # 只返回 release_at <= as_of 的观测
    ) -> MacroSeriesSnapshot: ...

# MacroSeriesRef: { source: str, code: str, region: str | None }
#   —— 与数据表 UNIQUE(source, code) 对齐，不再用裸 code（同 code 可能多源）

class SentimentDataProvider(Protocol):
    async def signals(self, ref: InstrumentRef, window: DateWindow) -> list[Signal]: ...
```

每个返回对象统一携带来源元数据：`source` / `source_url` / `retrieved_at` / `as_of`（或 `observation_period`）/ `release_at`（宏观/基本面）/ `freshness` / `data_gap`（可降级源缺失时）。

**宏观时点口径铁律（必须项 5/6）**：辩论/分析取宏观数据一律带 `as_of`，Provider 只选 `release_at <= as_of` 的观测，**杜绝用尚未发布的未来数据**。要点：
- **Ref 与表键一致**：`series(ref, as_of)`，`MacroSeriesRef` 含 `source+code+region`，对齐 `macro_series` 的 `UNIQUE(source, code)`——同一指标代码在不同源（东财/统计局/金十）是不同序列，裸 code 会串。
- **修订值选择**：同 `(series, observation_period)` 多次修订时，取 `release_at <= as_of` 中最新一版；`revision_hash NOT NULL`。
- **`release_at` 缺失策略（必须项 6）**：AKShare 各接口发布日期字段不统一，**无法确认发布时间的观测进 `data_gap`，绝不用 `retrieved_at`（抓取时间）冒充 `release_at`**——冒充会让"未来数据"混入历史决策。
- 每指标明确 `unit` / `frequency` / `value_type`（同比/环比/绝对值）。

## 7. LangGraph 辩论工作流

### 7.1 为什么此刻用 LangGraph（摆正预期）

现有辩论文档 §2.1 判定"JS 版 LangGraph 不成熟，自研编排足够"——在 Node 下这是**正确**的。切到 Python 后前提变了：LangGraph Python 成熟，`langchain-openai` 原生集成。但要清醒：当前流程（四分析师并行→多空对辩→裁判→风控）是**固定 DAG**，LangGraph 此刻的增益主要是**检查点恢复**和**清晰的图声明**，而非"更聪明"。真正价值在未来演化（动态分支、多轮循环、条件路由、人在环节）。按此预期投入，不神化。

### 7.4 失败与恢复（裁剪版）

| 场景 | 处理 |
|---|---|
| 单数据源超时 | Provider 返 data_gap，其余证据继续 |
| 单分析师失败 | 节点内重试；失败则保留角色失败态，辩论继续（不整体挂） |
| 裁判失败 | 任务标 failed，可从检查点重跑裁判节点 |
| 进程重启 | LangGraph `PostgresSaver` 检查点恢复；procrastinate 重试；无检查点的 running 任务超时后标 failed |
| 全部关键证据缺失 | 产出"证据不足"结论，不给确定性操作建议 |
| **发起者未配 BYOK key** | 任务直接 `llm_unavailable` + "请先在设置配置你的 LLM Key"，**不用他人 key**（§9.5） |
| worker 进程重启 | procrastinate 重新领取 + LangGraph 检查点续跑；任务幂等不重复建报告 |

每次辩论设护栏：最大时长、最大 LLM 调用数、token 预算、节点超时、取消标记。

> **Checkpoint 加密（Review R4/§12.2）**：LangGraph checkpoint 的 State 含持仓数量成本、私有研究假设、LLM prompt/输出——属敏感数据。用加密 Serializer，密钥 `LANGGRAPH_AES_KEY`；State **不存 BYOK 明文、不存完整 Authorization 头**；`graph_thread_id` 不作为前端查询权限依据，查询前先验 `debates.owner_id`。

### 7.5 执行载体（独立 worker + procrastinate）

多用户下辩论改为**队列 + 独立 worker**：

1. `POST /api/v1/debates`：同事务内插 `debates(status='queued', owner_id=当前用户, execution_owner_id=当前用户)` + `run_debate.configure(connection=conn).defer(...)`（§4.7 同事务原子入队），立即返回 id。
2. worker 由 **procrastinate** 领取 job（底层 `SKIP LOCKED`，自带租约/重试，**业务代码不手写**）；`graph_thread_id` 服务端生成，前端不可提交。
3. worker 取 `execution_owner_id` 的 BYOK key（解密后仅驻内存），构造 `ChatOpenAI` 跑 LangGraph 图，逐节点回写 progress/stage。
4. `PostgresSaver` 检查点：worker 崩溃后 procrastinate 重试 + 检查点续跑；任务幂等，不重复建报告。
5. 前端轮询 `GET /api/v1/debates/{id}`（复用 `useAnalysisPoller`，120s 超时上限）。SSE 列 M9 增强。

单 worker 起步即满足 <10 人；worker 无状态，加并发只需多起副本，procrastinate 保证不重复领取。

### 7.6 动态调度：DB 可改的任务时间如何生效（三轮 review 必须项 4）

问题：procrastinate 原生 cron 适合**代码里固定声明**的周期任务，但现有 `automation_tasks.schedule` 是**数据库里可随时改**的时间（如"每日 15:30"，用户可在设置页改）。二者不直接兼容。

**决策：dispatcher 模式（保留 DB 动态配置，不退化为固定 cron）**：
- procrastinate 注册**一个固定的每分钟周期任务** `tick_scheduler`（代码级 cron，`* * * * *`）。
- `tick_scheduler` 每分钟跑：读 `automation_tasks` 中 `enabled=true` 的任务 → 比较当前时间与 `schedule` → 到点且当天未跑过的，defer 一个实际业务任务（如日报生成）。
- **保留现有 `scheduler.js:26` 的语义**：先占位（记 `last_run=当天`）再执行，重叠防护（上一次没跑完跳过本次），单任务失败不影响其他。
- DB 改 `schedule` 后**下一分钟 tick 自然生效**，无需重启、无需重新声明 cron。

这样：procrastinate 仍是唯一调度器（`tick_scheduler` 是它的固定 cron），动态时间配置留在 DB，worker 持有 dispatcher。多 worker 下 `tick_scheduler` 每分钟只被一个 worker 领取，占位记录（`last_run`）再防同一业务任务重复 defer。

## 9. 鉴权、授权、安全、配置

### 9.1 鉴权：数据库 Session（Review R6，替代 v1 无状态 cookie）

v1 用 itsdangerous 无状态签名 cookie，**无法撤销**（禁用用户/改密后旧 cookie 仍有效）。多用户下改**数据库 session**：

- 密码 **argon2**（`argon2-cffi` 的 `PasswordHasher`）；登录对不存在用户也跑一次 dummy hash，减少用户名枚举时间差。
- 登录成功：生成高熵随机 token → DB 存其 HMAC 摘要（`sessions.token_hash`）→ 下发 `HttpOnly; Secure; SameSite=Lax` cookie（只放 token，不放 role）。
- 每请求：cookie token → 查 `sessions` 校验过期/撤销 → 查 `users` 拿**最新** role/status（不信 cookie 里的 role）→ 注入 `CurrentUser`。
- 支持：禁用用户即时失效、改密撤销全部 session、单设备登出、超管撤销指定 session。
- `Depends(get_current_user)` / `Depends(require_superadmin)` 两级依赖。
- 安全护栏：未配置超管时禁止对外监听（等价 `assertHostIsSafe`），除非显式 `ALLOW_INSECURE_HOST`。

### 9.2 CSRF（Review R6）

登录后写请求（double-submit）：`Origin` 匹配允许前端源 + `Content-Type: application/json` + `X-CSRF-Token` 与非 HttpOnly CSRF cookie 一致。

**匿名端点（login/register）的 CSRF 流程明确**：登录/注册时用户还没有 session，故：
1. 前端先 `GET /api/v1/auth/csrf`（匿名可访问）→ 服务端下发一个 itsdangerous 签名的 CSRF token（非 HttpOnly cookie + 响应体各一份）。
2. `POST /auth/login|register` 时带 `X-CSRF-Token` 头，服务端校验签名有效 + 与 cookie 一致 + `Origin` 合法。
3. 登录成功后换发正式 session cookie + 新 CSRF token。

`/reports/import` 走 Import Token（非 cookie 鉴权），**不吃 CSRF**（无 cookie 无 CSRF 面），但校验 token + 可选 IP allowlist。三类匿名端点（login/register/import）各自定义规则，不统一放宽。

### 9.3 邀请码注册

`POST /api/v1/invites`（超管）生成随机码 + `expires_at`，**仅返回一次明文**（DB 只存 `code_hash`）。`POST /api/v1/auth/register`（公开）用原子 `UPDATE invite_codes SET used_by... WHERE used_at IS NULL AND revoked_at IS NULL AND expires_at > now()`，受影响行数=1 才在同事务建 member 用户，防并发复用。无开放注册端点。

### 9.4 授权层（防越权，多用户核心风险）

隔离资源（`positions`/`watchlist_items`/`debates`/`user_llm_configs`）与私有报告：

- **Repository 查询层加 owner 条件**（不在 Python 内存里过滤后返回），无权访问统一返回 **404**（不泄露存在性）。
- **超管无特权**：超管对他人隔离资源同样 404（完全隔离）；超管特权仅限用户管理/邀请码/系统任务等**系统管理职能**，不延伸到他人业务数据，**无跨用户读后门**。
- 报告：`GET /reports` 查询 `visibility='shared' OR owner_id=current_user`；标星/归档/已读只写 `user_report_states`；`publish` 仅超管。
- 公共资源所有登录用户可读；写入（信号同步/报告导入/宏观刷新）限超管或系统任务。
- **报告 HTML 内容**经 FastAPI 属主/可见性校验后流式返回，**Caddy 不直接暴露 `data/reports/`**（对齐现有 `index.js:47` 鉴权语义）。

集成测试专项：A 访问 B 的持仓/辩论/私有报告→404；**超管访问成员隔离资源→同样 404**；共享报告所有人可读、个人态互不影响。

### 9.5 BYOK 全链路 + 执行身份（Review R3，扩展 v1）

**Review R3 指出 v1 只覆盖辩论**。实际 research/信号抽取/持仓分析/系统日报都调 LLM。引入 `LlmExecutionContext`：

```python
class LlmExecutionContext:
    execution_owner_id: UUID   # 用谁的 key
    request_actor_id: UUID | None
    purpose: Literal["research","stock_analysis","position_analysis",
                     "signal_extraction","debate","scheduled_briefing"]
    run_id: str
```

执行身份规则：用户手动研究/分析/辩论 → 当前用户；系统日报/信号抽取/超管手动同步 → 超管账号。**任何 LLM 调用都必须带 context**；无执行身份或其未配 key → 明确 `llm_unavailable`，**绝不隐式回退全局 key**。

### 9.6 BYOK 密钥安全（安全红线，最高优先级）

1. **加密存储**：key 用 Fernet 加密存 `user_llm_configs.api_key_ciphertext`；Fernet 密钥由 `BYOK_MASTER_KEY` 派生（**独立于 session 密钥**，见 §9.8）。
2. **绝不明文出现在三处**：日志（`logs` 写入前脱敏、异常堆栈不带 key）、前端回显（`GET /settings/llm` 只返 `configured`+掩码 `sk-****abcd`+providerHost+model，**不返密文/完整 URL 敏感参数**）、报告 JSON（`debates.report` 与证据快照不含 key）。
3. **最小驻留**：worker 执行时才解密，仅驻内存。
4. **未配 key**：发起者无配置 → 任务 `llm_unavailable` + 明确提示。
5. **无全局共享 key**（纯 BYOK）；`key_version` 字段预留，**完整轮换 rewrap 本期不实现**（§16）。

### 9.7 LLM URL SSRF 防护（Review R5，v1 遗漏）

用户自填 `api_url` 经 `LlmEndpointPolicy` 校验：scheme 仅 `https`（开发允许显式 `http://localhost`）；禁回环/私有/链路本地/云元数据 IP；**DNS 解析后的 IP 重新校验**；禁跨主机重定向；默认 allowlist（OpenAI/OpenRouter/DeepSeek 等），自定义域名需超管在系统配置放行；固定超时/响应体大小/重试上限；日志只记 host/status/latency，不记 Authorization。

### 9.8 密钥分离与配置（Review R4）

三个密钥**职责分离**（低成本、高收益，采纳）：

```text
DATABASE_URL
SESSION_SECRET       # session token HMAC
BYOK_MASTER_KEY      # 用户 LLM key Fernet 加密（丢失=用户 key 不可恢复，部署文档写明备份责任）
LANGGRAPH_AES_KEY    # LangGraph checkpoint 加密（checkpoint 含持仓/私有假设，见 §12.2）
SUPERADMIN_USERNAME / SUPERADMIN_PASSWORD   # 首启/迁移初始化超管
IMPORT_TOKEN / COOKIE_SECURE / ALLOW_INSECURE_HOST / MACRO_PROVIDER_CONFIG
# 无全局 LLM_API_KEY（改 BYOK）
```

env 保留 `FINANCE_KNOWLEDGE_*` 前缀。`.env` 不提交，`.env.example` 更新为多用户版。

### 9.9 LLM 安全边界（继承辩论文档 §5.4）

统一超时/重试/token 上限；输出 Pydantic 校验；Prompt 明确禁止编造缺失数据；原始数据/模型输出/最终报告分层保存；报告强制免责声明。

### 10.1 Docker Compose（4 服务）


- **`data/reports/` 不被任何静态服务器直接暴露**，报告内容只能走鉴权接口。

**构建与镜像**：多阶段构建——Node 阶段 `vite build` 产出 `frontend/dist`，**只拷入 caddy 运行镜像**（caddy 服务静态）；Python 阶段构建 api/worker 镜像（**不含前端 dist**，api/worker 同镜像不同入口）。`infra/caddy/Caddyfile` 配域名自动签发证书。不想开公网端口可改用 Cloudflare Tunnel，连 Caddy 都省。

## 12. 风险与应对

| 风险 | 影响 | 应对 |
|---|---|---|
| **app.db-wal 未落盘漏数据** | 迁移丢最新数据 | 迁移前强制 `wal_checkpoint(TRUNCATE)`（已列入 M1 步骤 2） |
| 5 万行 daily_bars 迁移慢/超时 | M1 卡住 | bulk 分批插入；校验行数比对 |
| 报告 HTML 与 DB 记录不一致 | 报告打不开 | 双向存在性校验（§5.2） |
| 业务逻辑重写引入隐性 bug | 功能回归 | 现有 2228 行测试作为行为规格逐个对照；纯函数（压力指数/技术指标）先迁先测 |
| **越权访问他人隔离数据** | 数据泄露 | 服务层统一属主校验；集成测试专测 A 访问 B 资源→404；列表默认按 owner 过滤 |
| **BYOK key 泄露**（日志/回显/报告） | 用户凭证外泄 | Fernet 加密落库；日志脱敏；前端仅掩码；报告不含 key；异常堆栈不带 key |
| **邀请码被猜测/复用** | 未授权注册 | 随机不可猜 code；过期机制；注册事务内原子标记 used，防并发复用 |
| **worker 重复领取任务** | 重复辩论、重复烧 key | procrastinate 内建领取（`SKIP LOCKED`）+ queueing lock；同 debate 幂等键，任务函数只更新不重复建报告 |
| akshare 接口不稳/字段变 | 宏观采集失败 | Provider 隔离 + 契约测试 + data_gap 降级；akshare 不进业务层 |
| LangGraph/langchain 版本演进快 | API 变动 | 锁定版本（对齐个人规则：依赖 pin 精确版本）；封装在 llm/ 与 agents/ 隔离 |
| 同步 SQLAlchemy 阻塞事件循环 | 并发下卡顿 | 路由用 `def` 走线程池；仅外部抓取用 async；<10 人压力低 |
| LLM 输出不稳定 | 报告结构缺失 | Pydantic 校验 + 重试 + 节点级失败态 |
| 公网暴露面扩大 | 攻击面 | Caddy 自动 TLS；仅邀请注册；安全护栏；PG 不对外暴露端口 |
| 一期工作量大、战线长 | 拖延/烂尾 | 分里程碑交付，每个里程碑可运行可验证；先跑通核心闭环（M1-M8）再打磨前端 |

## 14. 关键架构决策记录（ADR）

- **ADR-001 后端 Python**：LangGraph、akshare 宏观、pandas 分析、后续量化都在 Python 生态；决策人主力语言，项目未上线，适合建长期运行时。
- **ADR-002 前端 React+TS+Vite**：React 生态与资料更广；TS + FastAPI OpenAPI 形成前后端契约。展示层由 Ducc 代写降低语言负担。
- **ADR-003 api + worker 分进程**（多用户下采纳 ChatGPT 草案）：多用户并发发起辩论，长耗时 LLM 任务不能占 API 进程；worker 独立可单独重启、单独扩副本。
- **ADR-004 PostgreSQL**：LangGraph 检查点、JSONB、并发写、任务队列、迁移能力。SQLite 一次性迁入后不再维护双库。
- **ADR-005 同步 SQLAlchemy 起步**：好写好调试；仅外部抓取局部 async。
- **ADR-006 PG 任务队列用 procrastinate（而非 Redis / 手写 SKIP LOCKED）**：已有 PG，任务量低；procrastinate 底层即 `FOR UPDATE SKIP LOCKED`，自带领取/租约/重试，省去手写；引 Redis 不划算（对齐 `AGENTS.md` 反腐化）。
- **ADR-007 Caddy 而非 nginx**：公网需 TLS，Caddy 自动签发证书 + 极简配置，契合小规模；可选 Cloudflare Tunnel 免反代。
- **ADR-008 BYOK（每用户自带 key，无全局 key）**：多用户下成本按人隔离、归属无歧义；配套 Fernet 加密 + 日志脱敏 + 掩码回显的密钥安全体系（安全红线）。
- **ADR-009 邀请码注册（超管生成、带过期 + 单次使用），非开放注册**：少数可信用户准入，杜绝陌生人注册，攻击面最小。
- **ADR-010 混合数据归属 + 超管完全隔离**：公共数据共享；报告默认私有可发布共享 + 个人阅读态分离；持仓/自选/辩论按 owner 隔离，**含超管在内任何人不能读写他人隔离数据**，无跨用户后门。
- **ADR-011 Provider 隔离外部源**：字段/稳定性会变，集中处理解析/重试/口径/降级，不扩散到业务与 Agent。
- **ADR-012 证券身份 `instruments` 提前到 M1**（Review R2 修正 v1）：`stocks.code` 主键无法支持多用户同证券，是前提非优化；同时收敛 `secid_map`。
- **ADR-013 SSE 延后到 M9 增强，轮询起步**：<10 人轮询压力可忽略，不提前引入 SSE 复杂度。
- **ADR-014 数据库 session 而非无状态 cookie**（Review R6）：多用户需即时撤销（禁用/改密），无状态签名 cookie 做不到。
- **ADR-015 argon2 密码哈希**（Review R13，M0 定案）：OWASP 首选，passlib 维护停滞；**直用 argon2-cffi**（pwdlib 0.3.0 仍 Beta，本项目只需 argon2 一种，不需多算法封装糖）。
- **ADR-016 三密钥职责分离**（Review R4）：SESSION_SECRET / BYOK_MASTER_KEY / LANGGRAPH_AES_KEY 各司其职，低成本高收益；BYOK_MASTER_KEY 丢失=用户 key 不可恢复，需备份。
- **ADR-017 LLM 调用统一 `LlmExecutionContext`**（Review R3）：BYOK 覆盖全部 LLM 场景（研究/分析/信号/辩论/日报），非仅辩论；无身份或未配 key 明确失败，不回退全局 key。
- **ADR-018 procrastinate 唯一队列 + 周期任务归 worker**（Review R7/R14）：不手写 SKIP LOCKED、不双队列；周期调度由 worker 持有，避免多 API 进程重复触发。
- **ADR-019 Caddy 独占静态 / 报告内容经 FastAPI 鉴权**（Review R11）：Caddy 不暴露 `data/reports/`，私有报告经属主校验流式返回。
- **ADR-020 debates.id 用 ULID**（二轮 review）：`debate-{code}-{ts}` 多人同标的并发会碰撞；ULID 全局唯一且时序可排。
- **ADR-021 宏观数据强制 `as_of` 时点口径**（二轮 review）：Provider 只返 `release_at<=as_of` 的观测，杜绝未来数据；`macro_series` 按 `(source,code)` 唯一、`revision_hash NOT NULL`。
- **ADR-022 迁移校验用"映射账本"而非"行数相等"**（二轮 review）：stocks/reports/secid_map 是拆分合并，逐条对账映射数，不套等行数。
- **ADR-023 `decisions` 只读归档、冻结写入**（二轮 review）：旧每日指南历史保留可查，新能力由 debates 承载，不再写 decisions。
- **ADR-024 SignalsPage 确认/忽略走用户态表**（二轮 review）：信号本体公共不可被成员改删，`user_signal_states` 承载各人确认/忽略。
- **ADR-025 入队事务走 psycopg2 同事务 defer**（三轮 review P0，M0 定案）：SQLAlchemy+psycopg3 无官方同事务连接器；改 **psycopg2 + `SQLAlchemyPsycopg2Connector`**，`configure(connection=conn).defer()` 与业务写同一 SQLAlchemy 事务原子提交，**删除 outbox 子系统**。psycopg3 新特性本项目用不到。
- **ADR-026 报告全字段迁移**（三轮 review）：type_label/origin_label/local_date/highlights 保留，accent/wiki_path 进 meta，status/starred/archived 迁 user_report_states，无字段丢失。
- **ADR-027 证券身份规范化键 `(exchange, asset_class, canonical_symbol)`**（三轮 review）：实测代码前缀/市场标签混杂，`(market,code)` 不稳；`market` 降为展示字段，各源标识入 `provider_ids`。
- **ADR-028 动态调度用 tick_scheduler dispatcher**（三轮 review）：DB 可改的 `automation_tasks.schedule` 由每分钟固定 cron 读取投递，兼顾"唯一调度器"与"DB 动态生效"。
- **ADR-029 `settings` 归系统管理数据（超管专属）**（三轮 review）：修正 v3 "公共共享"与"/settings 仅超管"的矛盾。
- **ADR-030 宏观 `release_at` 缺失进 data_gap，不用抓取时间冒充**（三轮 review）：AKShare 发布日期字段不统一，冒充会让未来数据混入历史决策。
