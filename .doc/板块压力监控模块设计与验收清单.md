## 一、背景与动机（Context）

### 1.1 灵感来源

投资群里的玩法：把 4 个 proxy 指标归一化后等权平均，合成一个 0-100 的「压力指数」：

- SOXX 量比（成交量 / 20 日均量）
- SOXX vs XLU 背离（高 beta 相对防御跌多少）
- VIX − VIX3M（恐慌 / 期限结构）
- SPY vs SOXX 背离（大盘 vs 半导体分化）

越接近 100 = **放量抛售 + 半导体下杀 + 恐慌上升 + 资金逃离高 beta** 的四维度崩盘；低量反弹 + 压力回落到低位则是「下跌尾声」信号。

### 1.2 本项目的差异化价值

群友监控的是**市场**；本项目监控的是**用户自己的暴露**——组合分析已能把持仓穿透到底层主题（`buildThemeRows`，`src/lib/portfolio-analysis.js:168`）。MVP 先用两个固定主题验证「指标与盘面的对应关系」，跑通闭环后再泛化到「按持仓权重自动派生监控对象」（见「六、MVP 边界」）。

### 1.3 对群友原版的两点改进

1. **归一化用滚动百分位（percentile rank），不用 min-max**：min-max 对窗口内极值极敏感，一根异常 K 线就压扁量纲；滚动百分位天然 0-100 且稳健。
2. **保留并展示分项**：综合分只用于阈值报警，真正有信息量的是分项形态——「低量反弹 + 压力回落」与「放量下跌」的区别藏在量比单项里，只给一个总分会丢掉这个信息。

## 二、代理标的与数据源

### 2.1 分项与代理标的（按已确认的默认组合）

| 分项 | A股半导体（3 项） | 美股半导体（4 项） | 危险方向 |
|---|---|---|---|
| ① 量比 | 512480 半导体ETF（`1.512480`） | SOXX（`105.SOXX`） | 放量 ↑ = 危险 |
| ② 高beta vs 防御背离 | 512480 vs 510880 红利ETF（`1.510880`） | SOXX vs XLU（`107.XLU`） | 板块跑输防御 = 危险 |
| ③ 大盘 vs 板块背离 | 沪深300 vs 512480（`1.000300`） | SPY vs SOXX（`107.SPY`） | 板块跑输大盘 = 危险 |
| ④ 恐慌度（仅美股） | —（MVP 不做） | VIX − VIX3M（`^VIX` / `^VIX3M`） | backwardation ↑ = 危险 |

> A股半导体没有直接对应的 VIX/VIX3M 期限结构，MVP 明确降级为 3 分项，不用波动率替代（避免引入含混口径）。

### 2.2 数据源与接口

**东财日线**（A股 ETF + 美股 ETF）：
```
https://push2his.eastmoney.com/api/qt/stock/kline/get
  ?secid={secid}&klt=101&fqt=1
  &fields1=f1,f2&fields2=f51,f53,f56
  &beg={YYYYMMDD}&end=20500101&lmt=250
```
- `klt=101` 日线，`fqt=1` 前复权。
- `fields2=f51,f53,f56` 实测解码为 `date,close,volume`（完整 7 字段序为 `f51..f57 = date,open,close,high,low,volume,amount`，本模块只取收盘价与成交量）。
- 返回 `data.klines` 为逗号分隔字符串数组，`data` 为 `null` 表示 secid 无效。
- 需带 `User-Agent` 头（无 UA 时美股标的偶发空响应 / 超时）。

**Yahoo VIX / VIX3M**（美股恐慌度分项）：
```
https://query1.finance.yahoo.com/v8/finance/chart/^VIX?interval=1d&range=1y
https://query1.finance.yahoo.com/v8/finance/chart/^VIX3M?interval=1d&range=1y
```
- 取 `chart.result[0].timestamp`（秒级）+ `chart.result[0].indicators.quote[0].close`。
- 实测 1 年约 260 个点，含少量 `null`（需按 timestamp 对齐时过滤掉 null）。
- `^` 需 URL 编码为 `%5E`。

## 三、架构与数据流

### 3.1 数据流

```
daily-job.runDailyJob (收盘后触发，跟随现有日更调度)
  ├─ syncDailyBars(所有 secid)            → UPSERT 落 daily_bars 表（天然幂等）
  └─ runPressureMonitor()
        ├─ 读 daily_bars → pressure-index 纯计算 → 两主题当日分 + 序列
        ├─ 跨阈值(上穿70 / 下穿30) → replaceCommunitySignalSnapshot 写信号流
        └─ 运行快照写 settings（lastPressureRun 等）

前端 Today 页 → GET /api/pressure → 后端现算两主题(最新分 + 近30日 + 分项) → 压力卡片
```

### 3.2 核心设计决策

- **`daily_bars` 是唯一新表**：日线是唯一需要持久化的原始数据。
- **压力分不落快照表、每次请求现算**：`daily_bars` 已持久化 + `pressure-index` 是纯函数，`GET /api/pressure` 时现算即可；跨阈值判定只需取序列末尾两点。避免「原始数据 + 派生分数」双份状态与同步问题，保持数据源单一。
- **VIX/VIX3M 也落 `daily_bars`**：用统一的 `secid` 命名（如 `YAHOO.VIX` / `YAHOO.VIX3M`）复用同一张表与同一套取序列逻辑，`kline-store` 内按 secid 前缀分派到东财 / Yahoo 两个 fetcher。
- **监控失败不阻断日更主流程**：`runPressureMonitor` 包 try/catch，异常仅 `appendLog`，不影响每日简报生成。

### 3.3 计算方法（`lib/pressure-index.js`，纯函数）

对每个主题、每个分项，先产出一条统一为**越大越危险**的原始危险度序列：

1. **量比**：`vr = vol / SMA20(vol)`，direction = +1
2. **高beta背离**：`danger = -(retN(板块) − retN(防御))`，`retN` = N 日简单收益率（MVP N = 5）
3. **大盘背离**：`danger = -(retN(板块) − retN(大盘))`
4. **恐慌度**：`danger = VIX − VIX3M`，direction = +1（仅美股）

再对每条危险度序列按**滚动窗口 120 交易日**算「当前值在窗口内的百分位」→ 分项分 `0..100`；等权平均 → 综合压力分。

- 同主题标的按 `date` 做 inner-join 对齐（A股同为沪深交易日历；VIX 与 SOXX/SPY/XLU 同为美股日历，天然可对齐）。
- 窗口长度、收益期 N、阈值等设为具名常量或入参，便于后续校准。

导出签名：
```js
computeThemePressure({ bars, config }) → {
  date,                                   // 最新交易日
  composite,                              // 0..100 综合压力分
  subScores: [{ key, label, score, rawText }],  // 各分项分 + 原始值文案
  series30: [{ date, composite }],        // 近 30 日综合分序列（画 sparkline）
  status                                  // 语义化状态文案（见 3.4）
}
```

### 3.4 语义化状态（规则生成，非 LLM）

量比方向 × 综合分方向的四象限：

| 综合分 | 量比 | 状态文案 |
|---|---|---|
| ↑ | 高 | 放量下跌，压力抬升中 |
| ↓ | 低 | 低量企稳，压力回落（尾声信号） |
| ↑ | 低 | 缩量阴跌 |
| ↓ | 高 | 放量反弹待确认 |

### 4.3 `daily_bars` 表结构

```sql
CREATE TABLE IF NOT EXISTS daily_bars (
  secid TEXT NOT NULL,
  date  TEXT NOT NULL,
  close REAL,
  volume REAL,
  updated_at TEXT,
  PRIMARY KEY (secid, date)

CREATE INDEX IF NOT EXISTS idx_daily_bars_secid_date ON daily_bars(secid, date);
```

## 五、阈值与信号沉淀（复用现有验证闭环）

- 综合分**上穿 70 / 下穿 30** 时，用 `replaceCommunitySignalSnapshot`（`server/routes/signals.js:81`）写一条 `community_signals`：
  - `source = "pressure-monitor"`、`theme` = 主题名（A股半导体 / 美股半导体）
  - `summary` 含当前综合分 + 主导分项（哪个分项贡献最大）
  - 进入现有「待验证 / 已证实 / 已证伪」体系（Signals 页 `src/pages/Signals.jsx`），长期积累「这个指标到底准不准」的证据。
- 阈值 70/30 是**百分位阈值**（当前压力处于历史窗口内前 30% / 后 30%），**非**群友原版的绝对值 30/100——换标的和归一化方法后绝对阈值含义已变，百分位阈值语义清晰、跨主题可比。

> ⚠️ 伪精确风险（务必记录）：下跌日里四个分项往往同涨（量比、背离、波动高度相关），等权平均未必真提供了四个独立维度的信息。因此第五节的「跨阈值写进信号验证闭环」不是锦上添花，而是判断这个模块**是否值得长期保留**的依据——若沉淀的信号验证准确率长期偏低，应果断下线或重构分项，而非继续堆维度。

## 六、MVP 边界（明确不做）

- ✋ 只做 A股半导体、美股半导体两个**固定**主题，暂不按持仓权重自动派生监控对象。
- ✋ 不建压力快照表、不做历史分数回放页。
- ✋ 阈值先用固定百分位 70/30，不做自动校准（留待有 ≥120 日数据后校准）。
- ✋ 不覆盖港股及其它板块。
- ✋ A股不引入波动率替代 VIX 维度，明确为 3 分项。

> 第二步（验证有效后）：主题从组合分析 `themeRows` 自动派生（权重 ≥10% 或前 3）+ 阈值报警常态化 + 压力分与持仓权重同屏（Portfolio 页）。

### 落地补充说明

- **kline-store 增加带退避重试**：数据源（尤其东财美股标的）偶发 `UND_ERR_SOCKET`/超时，加 `MAX_ATTEMPTS`（默认 3，env 可调）重试后再失败才计入 `syncFailures`，显著提高日更成功率。
- **两主题共用信号快照一次性写入**：两主题同 `source+date+sourceTitle`，`replaceCommunitySignalSnapshot` 按此三元组删旧插新，若分两次写后者会删掉前者，故 `runPressureMonitor` 收集全部跨阈值信号后一次写入。
- **信号 relatedAssets 用主题 secid 列表**：便于后续与决策/持仓关联。
