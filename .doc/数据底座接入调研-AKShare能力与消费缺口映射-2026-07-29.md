# 数据底座接入调研：AKShare 真实能力 × 项目消费缺口映射

> 调研日期：2026-07-29
> 评审基线：`main`（`2da044e`），后端 4 个数据 provider 全部为东财系
> 上游版本：AKShare 约 v1.18.74（文档最后更新 2026-07-24）
> 调研方法：直接拉取 AKShare 官方文档仓库原始 markdown（`github.com/akfamily/akshare/docs/data/**`）逐接口解析函数名+字段+目标地址；`gh api` 拉取近 200 条 GitHub issue 核对失效情况；对存疑接口读源码（`akshare/__init__.py`、`stock_feature/stock_a_indicator.py`）确认。**所有函数名均来自文档/源码真实存在，未凭记忆编造。**
> 关联文档：`全栈重构后产品与技术评审报告-2026-07-29.md`、`全栈重构后下一步迭代技术方案-2026-07-29.md`（本文是其 §5 Research Data Hub 的数据事实底座与接入清单）

## 0. 核心结论（TL;DR）

1. **最重要的发现不是"该补哪些指标"，而是单点依赖风险**：项目当前 4 个 provider（`eastmoney.py`/`eastmoney_finance.py`/`eastmoney_fund.py`/`eastmoney_macro.py`）**全部是东财**，而基于 200 条 issue 的结论是——**东财 `_em` 系是所有源里失效最集中的，且已上验证码/风控**。AKShare 的战略价值首先是引入官方源（中证/中债/巨潮/申万）做**多源冗余**，其次才是补数据广度。这改写了原方案 §5.5"AKShare 为主、东财降级"的表述：对部分数据，降级方向应反过来。

2. **四个消费拉动的真实缺口**：宏观流动性面残缺（仅 5 指标）、指数/ETF 成分为空、个股基本面浅且无分位、完全无"硬事件"面。

3. **一个可顺手修掉的诚实性妥协**：当前宏观 `release_at` 是**估算**（报告期 + 保守滞后天数），可用 jin10 系接口的真实发布日 / `stock_report_disclosure` 的实际披露日**从"估算"升级到"真实"**。

4. **两个必须避开的坑**：网络教程高频引用的 `stock_a_indicator_lg`（个股逐日 PE/PB）和 `index_value_hist_funddb`（韭圈儿指数估值）**已从当前版本 AKShare 移除**（读源码确认，仅存 changelog 痕迹）。个股逐日估值一律用 `stock_value_em`。

## 3. 诚实性升级：宏观 release_at 从"估算"转"真实"

**当前妥协**：`eastmoney_macro.py:45` `_estimate_release_at` 用"报告期 + 保守滞后天数"硬估（CPI 滞后 45 天、PMI 32 天、GDP/M2 50 天），宁可估晚不用未来数据。这是东财 datacenter 只给 `REPORT_DATE`（报告期）下的无奈之举。

**AKShare 提供的升级路径**：

- **jin10 系接口的"日期"列即真实发布日**：`macro_china_cpi_yearly`/`macro_china_ppi_yearly`/`macro_china_pmi_yearly`/`macro_china_gdp_yearly`/`macro_china_m2_yearly`。且**末行常为下一期"预测值"**，可直接当经济事件日历用。
- **财报侧**：`stock_report_disclosure`（巨潮预约披露）给"首次预约→变更→**实际披露日**"，是做 point-in-time 对齐财报的最佳来源。
- **准备金率**：`macro_china_reserve_requirement_ratio` 同时含"公布时间 + 生效时间"。

**反向的坑（必须配时点对齐，否则前视偏差）**：以下接口**只有报告期、没有发布日**——
- `stock_financial_analysis_indicator`（新浪，"日期"=报告期）、`stock_financial_abstract`、东财单只报表 `stock_*_sheet_by_report_em`（`REPORT_DATE`=报告期）。
- 东财 NBS 宏观系 `macro_china_cpi`/`macro_china_gdp`/`macro_china_money_supply`（月份/季度=参考期）。

**工程建议**：宏观核心序列用东财 NBS 系取干净"报告期→数值"面板，需要发布时点时叠加 jin10 系补真实发布日；财报用指标接口取值 + `stock_report_disclosure` 实际披露日对齐。**不要假设所有接口都有 release date。**

## 4. 单点依赖风险与源稳定性分级（基于 200 条 issue）

**现状**：项目 4 个 provider 全部东财。而东财是 issue 分布中失效最集中的源。

### 4.1 来源稳定性分级

| 级别 | 来源 | 代表接口 | 特征 |
|---|---|---|---|
| **最稳（应作核心底座）** | 交易所/官方 API | 中证 `*_csindex`、中债 `bond_china_yield`、巨潮 `*_cninfo`、上交所 `option_risk_indicator_sse`、申万 `sw_*`/`*_sw` | 走官方 API，改版少 |
| **中等，失效最集中** | 东财 `_em` 系 | `stock_zh_a_hist`、`fund_portfolio_hold_em`、`stock_value_em` | 已上**验证码/风控**，需 cookie 池 |
| **易碎（仅作补充）** | 雪球 `_xq`、乐咕 `_lg`、同花顺 `_ths` | `stock_individual_basic_info_xq`、`stock_buffett_index_lg` | 需登录态/token/csrf，列名常变 |

### 4.2 高频失效模式（issue 归纳）

1. 上游改版导致**分页参数变更** → JSONDecodeError（如 `stock_gdfx_free_holding_detail_em` #7355）。
2. 东财**验证码/风控**拦截 → 空结果或报错（issue #7119 给出手动方案：先访问 `quote.eastmoney.com` 抓 cookie 再带入）。
3. 上游**返回列名变化**（中英文切换）→ KeyError/列名不匹配（如 `stock_zh_a_disclosure_report_cninfo` #7336）。
4. **非交易时段**调用实时类接口返回空 → 抛异常（`fund_value_estimation_em` #7362/#7363/#7369）。
5. 网络层 `RemoteDisconnected`（#7330/#7333，重试可缓解）。

### 4.3 工程落地建议

- **优先官方源**（`_csindex`/`chinabond`/`_cninfo`/`sse`/`sw`）作核心底座；东财 `_em` 作主力但必须封装 **cookie 池 + 重试 + 列名容错 + 版本 pin**。
- 雪球/乐咕/同花顺系**仅作补充**，不进核心链路；对返回空/列缺失做防御式解析。
- **pin 住 akshare 版本**并订阅 release（当前约 v1.18.74），修复常伴随字段/函数变更；升级前跑接口回归测试。
- 每个 Adapter 保存脱敏真实 fixture，普通测试不打公网；关键接口配独立 `live smoke`。

### 4.4 AKShare 无法覆盖、需自建/外部源的能力

- **ETF 申赎清单（PCF，一篮子成分+现金替代）**：文档全文检索无 PCF 接口，AKShare 只提供申赎"状态"（`fund_purchase_em`）非申赎"清单"。需交易所 PCF 文件或券商接口。
- **期权看跌看涨比（PCR）**：无直接命名接口，需自行用认购/认沽持仓量或成交量计算。
- **期货展期收益率**：无专门接口，需用近远月合约（`futures_zh_daily_sina` 主力/次主力）自算。

- **净值/历史**：`fund_open_fund_info_em(symbol, indicator)`（indicator 是关键参数：单位净值走势/累计净值/累计收益率/同类排名/分红送配/拆分详情）；`fund_open_fund_daily_em`（全市场最新净值一览）；分类型 `fund_money_fund_info_em`(货币)、`fund_etf_fund_info_em`(场内)、`fund_hk_fund_hist_em`(香港)；`fund_value_estimation_em`（盘中估算，**近期高频报错**）。
- **持仓与资产配置（季频）**：`fund_portfolio_hold_em(symbol, date)`（股票持仓：代码/名称/占净值比/持股数/市值/季度）、`fund_portfolio_bond_hold_em`（债券持仓）、`fund_portfolio_industry_allocation_em`（行业配置）、`fund_portfolio_change_em`（重大变动）、`fund_individual_detail_hold_xq`（雪球大类资产比例）；巨潮聚合 `fund_report_asset_allocation_cninfo`、`fund_report_industry_allocation_cninfo`。**披露制度限制**：季报仅前十大重仓，半年报/年报才有全部持仓。
- **规模/经理/评级**：`fund_overview_em`（单只：规模/管理人/托管人/经理/费率）、`fund_aum_em`/`fund_aum_hist_em`（公司规模）、`fund_scale_change_em`、`fund_etf_scale_sse`/`fund_etf_scale_szse`；经理 `fund_manager_em`；评级 `fund_rating_all`（上海证券/招商/济安金信三家）、`fund_rating_sh`/`_zs`/`_ja`；雪球单只 `fund_individual_basic_info_xq`/`fund_individual_achievement_xq`/`fund_individual_analysis_xq`（年化波动/夏普/最大回撤）。

### D. 股票基本面与事件（A 股核心）

## 6. 接入顺序建议（按消费拉动，不按 AKShare 接口清单）

1. **宏观流动性补全 + release_at 转真实**（独立可做，不依赖主线2，性价比最高）——补社融 `macro_china_shrzgm` / LPR `macro_china_lpr` / 国债曲线 `bond_china_yield`，一箭三雕：**补广度 + 修诚实性妥协（jin10 真实发布日）+ 引入非东财官方源降单点风险**。同步扩 `roles.py:47` 宏观 prompt。
2. **指数/ETF 成分估值**（跟随主线2"任意标的辩论"一起做）——用户能搜任意 ETF 后最先撞空的就是它的基本面；接口全官方源、稳（`index_stock_cons_weight_csindex`/`sw_index_third_cons`/`stock_zh_index_value_csindex`）。
3. **个股估值分位 + 1~2 个高信号事件**（小切口，克制）——只接辩论真会引用的：`stock_value_em` 估值 + 龙虎榜/资金流二选一。分位自行拉历史算。
4. **基金穿透 / 商品 / 期权**（按需，有相关持仓再说）——每域先写消费场景 ADR 再接。

**贯穿原则**：每个数据集必须至少有一个明确消费者，避免无人使用的数据堆积；"量"不是价值，"每个数据都有真实消费者"才是。
