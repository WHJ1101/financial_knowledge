# 决策模块升级：多角色辩论式标的决策报告 — 设计与验收清单

> 日期：2026-07-13
> 实施复核：2026-07-16。原文的 Node/单模型实现路线已由 Python 全栈方案覆盖；当前实现采用 **LangGraph + PostgreSQL checkpoint + Procrastinate worker + 多 Profile BYOK**，技术/基本面/宏观/情绪、多方、空方、裁判、风控八个 Agent 均可独立配置模型。原文仍保留为业务契约与历史决策记录，实际技术验收见文末“十一、Python 多模型实现复核”。
> 需求来源：现「决策」页每日决策指南价值低（纯模板拼接、不调 LLM）。升级为：选一个持仓/自选标的 → 多角色 Agent 从技术/基本面/宏观/情绪四面辩论 → 产出含多空双方、分歧点、置信度、证伪条件、操作建议的决策报告。
> 当前方案：**LangGraph Python + 多模型多 Agent**；四分析师独立并行节点 → 多空开篇 → 交叉反驳 → 裁判裁决 → 独立风险复核。
> 验收基线：`npm test` 全绿（新增纯函数与路由用例）+ `npm run build` 通过 + 运行时后验冒烟。
> 数据源验证：基本面接口已于 2026-07-13 实测取到数（见附录 A）。
> 范围：本文只做**阶段一 MVP 闭环**；多 provider、专用宏观源、辩论准确率回测留阶段二（见 §九）。

## 一、背景与口径声明（务必先读）

### 1.1 现状问题

`server/routes/decisions.js` 的 `createDailyDecision()` **完全没有调用 LLM**：把 `positions`/`stocks`/`indices` 拼成模板字符串，`positionAdvice` 直接抄 `positions.reason`。所谓"每日决策指南"是静态汇总，不产生新洞察，用户判断"价值不大"成立。

### 1.2 为什么做辩论式

辩论式的价值**不是"多 Agent 显得高级"**，而是：

1. **强制暴露分歧**：多空两方各自组织论据并反驳对方，逼出单模型一次成文时被"乐观叙事"掩盖的风险点。
2. **强制证伪条件**：裁判必须输出"什么事实出现则结论失效"，契合项目既有哲学（`server/services/stock-analyzer.js` 已强制"拒绝套话、要证伪条件"）。

### 1.3 【关键】数据诚实性声明

辩论四个数据面**真实性不均衡，必须诚实标注，禁止用模型训练记忆编造数据**：

| 数据面 | 数据源 | 真实性 |
|---|---|---|
| 技术面 | `daily_bars` 日线 → 纯函数指标 | ✅ 真实 |
| 基本面 | 东财 push2 `stock/get` 估值快照 | ✅ 真实（附录 A 实测）|
| 情绪面 | `community_signals`（97 条）按标的/主题过滤 | ✅ 真实 |
| 宏观面 | 大盘指数 + 宏观类信号（**无专用宏观源**）| ⚠️ 半真：代理观点，置信度低 |

处置：每个分析师角色的证据缺失时**必须在 `dataGaps` 字段声明**；裁判对 `dataGaps` 非空的面**降权**；报告 UI 显式标注宏观面为"轻量代理"。

### 2.1 核心设计决策

- **自研编排，不用 LangGraph.js**：LangGraph 以 Python 为主、JS 版不成熟；单辩论流程无需图引擎，用 `Promise.all` + 顺序 `await` 足够。零新依赖，契合项目全自研 pipeline 风格。
- **单模型多角色**：靠不同 system prompt 让同一模型扮演技术/基本面/宏观/情绪分析师 + 多空辩手 + 裁判。阶段二再考虑多 provider 对辩。
- **异步任务化 + 轮询**：一次辩论 7-9 次 LLM 调用（约 30-60s），必须 fire-and-forget（仿 `stock-analyzer.js:analyzePosition` 不 await 模式）+ 前端轮询进度（仿 `useAnalysisPoller`），不能同步阻塞请求。
- **纯编排与 I/O 分离**：`debatePipeline.js` 只做编排、依赖注入 llm 与 evidence，可 mock 单测（仿 `researchPipeline.js`）；真实取数在 `debate-service.js`。
- **数据诚实**：见 §1.3，dataGaps 强制声明 + 裁判降权。

### 2.2 辩论流程（时序）

```
startDebate(targetRef)
  │
  ├─[同步] 插入 debates(status=running, progress=0) → 返回 {id}
  │
  └─[异步 fire-and-forget]
       │
       ├─① ensureBars(secid)          ─ 该标的无日线则 fetchHistoricalExchangeBars 回补   progress=10
       │
       ├─② collectEvidence(target)    ─ 技术/基本面/情绪/宏观四面证据                     progress=25
       │
       ├─③ 四分析师并行 Promise.all   ─ technical/fundamental/macro/sentiment            progress=55
       │      每人输出 {stance, points[], confidence, dataGaps[]}
       │
       ├─④ 多空辩论各一轮             ─ bull 综合看多+反驳 / bear 综合看空+反驳           progress=80
       │
       ├─⑤ 裁判 judge                 ─ {verdict, confidence, keyDisagreements,          progress=95
       │      bullCase, bearCase, falsifiers[], action, disclaimer}
       │
       └─⑥ UPDATE debates(status=done, report=JSON, progress=100)
              失败任一步 → status=failed + errorReason（前端错误态，不崩）
```

## 三、数据契约

### 3.1 辩论标的引用 `targetRef`

```js
// POST /api/debates 请求体
{ code: "301308", name: "江波龙", market: "创业板", quoteSecid: "0.301308", source: "stock"|"position" }
```

### 3.2 四面证据 `evidence`（collectEvidence 产出）

```js
{
  technical:   { bars: N, maShort, maLong, chg5d, chg20d, volatility, volumeRatio, lastClose } | { dataGap: "无日线" },
  fundamental: { pe, pb, roe, revYoy, profitYoy, mktCap } | { dataGap: "估值接口无数据" },
  sentiment:   { signals: [{date, summary, signalType}], recentChgPct } | { dataGap: "无相关信号" },
  macro:       { indices: [{name, changePct}], macroSignals: [...], note: "轻量代理，非专用宏观源" }
}
```

### 3.3 单角色分析师输出（LLM 返回 JSON）

```js
{ stance: "bull"|"bear"|"neutral", points: ["论据(附具体数据)"], confidence: 0-100, dataGaps: ["缺失项"] }
```

### 3.4 最终报告 `report`（落库 debates.report，JSON）

```js
{
  target: {code, name, market},
  analysts: { technical, fundamental, macro, sentiment },   // 各自 §3.3 结构
  debate:   { bull: {points[], rebuttal}, bear: {points[], rebuttal} },
  judge: {
    verdict: "偏多"|"偏空"|"中性",
    confidence: 0-100,
    keyDisagreements: ["多空核心分歧"],
    bullCase: "看多逻辑摘要",
    bearCase: "看空逻辑摘要",
    falsifiers: ["证伪条件：什么事实出现则结论失效"],
    action: { stance: "加仓/减仓/持有/观望", trigger: "触发条件", stopLoss: "止损/风控" },
    dataCaveats: ["数据面局限，如宏观为代理"]
  },
  disclaimer: "本报告为 AI 多角色辩论推演，非投资建议，不构成买卖依据。",
  generatedAt: ISO
}
```

### 3.5 `debates` 表

```sql
CREATE TABLE IF NOT EXISTS debates (
  id TEXT PRIMARY KEY,           -- debate-{code}-{ts}
  target_code TEXT NOT NULL,
  target_name TEXT,
  target_market TEXT,
  status TEXT DEFAULT 'running', -- running | done | failed
  progress INTEGER DEFAULT 0,    -- 0-100
  stage TEXT,                    -- 当前阶段文案（回补/取证/分析/辩论/裁决）
  verdict TEXT,                  -- 裁判结论(冗余出来便于列表展示)
  confidence INTEGER,
  report TEXT,                   -- 完整报告 JSON(§3.4)
  error TEXT,
  created_at TEXT NOT NULL,
  updated_at TEXT
);
CREATE INDEX IF NOT EXISTS idx_debates_created ON debates(created_at);
```

## 五、关键实现约束

### 5.1 异步与进度（复用现有范式）

- `startDebate` 同步插 `running` 记录、立即返回 `{id}`，**不 await** 辩论过程（仿 `stock-analyzer.js:52 analyzePosition` fire-and-forget）。
- 每阶段 UPDATE `progress`/`stage`，前端轮询 `GET /api/debates/:id` 直到 `status!=running`（仿 `Portfolio.jsx:useAnalysisPoller` 轮询范式，间隔 ~2s，done/failed 停止）。
- 轮询要有**超时上限**（如 120s）防止卡死态无限轮询。

### 5.2 降级（不崩）

- LLM 未配置（`isLlmConfigured()` false）：`startDebate` 直接落 `failed` + 明确原因，前端提示"未配置 LLM"。
- 单角色 LLM 调用失败/解析失败：该角色标 `dataGaps` 降级，辩论继续（不因一个分析师挂掉而整体失败）。
- 全部角色失败：debate `failed` + 原因。
- 每次 LLM 调用走 `callChatCompletion` 现有超时（阶段一沿用，不额外重试以免辩论过长）。

### 5.3 ensureBars（自选股日线按需回补）

自选股（江波龙等 9 只）日线**不在 daily_bars**（此前只回补 14 只持仓）。辩论前：`getAllBars(secid)` 为空则调 `fetchHistoricalExchangeBars(secid)` 回补落库；港美股/无 secid 标的技术面标 `dataGap`，辩论仍继续（靠其余三面）。

### 5.4 安全与合规

- 报告**强制免责声明**（§3.4 disclaimer），前端始终显示。
- 操作建议措辞为"推演倾向 + 触发/风控条件"，非"必涨/保证收益"。
- 路由全部受 auth gate（非 public）。
- 无硬编码密钥；LLM key 走 env（现有 `resolveLlmApiKey`）。

## 七、成本与风险

| 风险 | 说明 | 缓解 |
|---|---|---|
| LLM 延迟/成本 | 单次 7-9 调用 30-60s | 异步任务化 + 轮询进度；阶段一不做多 provider |
| 数据面不均衡 | 宏观无专用源、基本面依赖单接口 | dataGaps 强制声明 + 裁判降权 + UI 标注 |
| 辩论和稀泥 | 折中平庸结论 | 裁判 prompt 强制输出分歧点+证伪条件+明确 verdict |
| 自选股无日线 | 技术面空 | ensureBars 按需回补 |
| 口径误读 | 用户当真投资建议 | 强制免责声明 + 措辞为推演倾向 |
| 东财接口不稳 | 估值接口偶发超时 | 超时降级 dataGap，不阻断辩论 |

## 九、明确不做（阶段二）

- 多 provider 对辩（不同厂商模型扮多空）。
- 专用宏观数据源（利率/CPI/社融/流动性）。

- 辩论轮数/角色可配置。
- 港美股基本面（东财接口对 A 股最全）。
